# Xmex 语言参考

本文写清楚**实际支持到什么程度** —— 语法像 Python 不等于语义完整,
这里的每一行都是照着能跑通的实现写的。

## 支持的语法

### 字面量与类型

| 写法 | 类型 | 说明 |
|---|---|---|
| `42`、`-7` | int | 64 位有符号,**不会**自动提升为任意精度 |
| `3.14`、`1.5e3` | float | |
| `"text"`、`'text'` | str | 转义支持 `\n \t \r \\ \' \" \0`;**不可变** |
| `True`、`False` | bool | |
| `None` | None | |
| `[1, 2, 3]` | list | **可变**,支持尾随逗号 |
| `(1, 2)` | tuple | 不可变。**由逗号决定**:`(1)` 是 `1`,`(1,)` 才是单元素元组 |
| `{"a": 1}` | dict | 插入有序,**可变** |

### 运算符(优先级与 Python 一致)

```
or  →  and  →  not  →  比较  →  + -  →  * / // %  →  一元 -  →  **  →  后缀
```

几个容易踩的点,都已经按 Python 语义实现:

- `-2 ** 2` 是 `-(2 ** 2)` = `-4`,不是 `4`
- `**` 右结合:`2 ** 3 ** 2` = `2 ** 9` = `512`
- `not` 优先级低于比较:`not a == b` 等价于 `not (a == b)`
- `7 / 2` = `3.5`(真除法);`7 // 2` = `3`(向下取整)
- `-7 // 2` = `-4`,**不是** `-3` —— 向下取整,与 C++ 的向零取整不同
- `-7 % 3` = `2` —— 取模结果符号跟随除数
- `and` / `or` **返回操作数本身**,不是布尔值:`1 and 2` → `2`,`0 or 3` → `3`

`+` 与 `*` 对容器也成立:

| 表达式 | 结果 |
|---|---|
| `"ab" + "cd"` | `'abcd'` |
| `[1] + [2]` | `[1, 2]`(新列表) |
| `"ab" * 2`、`2 * "ab"` | `'abab'` |
| `[1] * 2` | `[1, 1]` |

**比较不支持链式写法**:`a < b < c` 会被解析成 `(a < b) < c`,与 Python 不同。

比较规则:

- `==` / `!=` **按值比较**,支持 int / float / bool / str / list / tuple / dict。
  字符串按字节比,列表与元组逐元素递归比,字典比较与插入序无关。
- `1 == 1.0` 是 `True`,`True == 1` 是 `True`。
- `1 == "a"` 是 `False`,**不报错**(与 Python 一致)。
- `<` `<=` `>` `>=` 只支持数值之间与字符串之间(按字典序),其余报运行时错误。

### 语句

```python
x = 1                    # 赋值
xs[0] = 9                # 下标赋值(列表按位置改,字典按键插入或更新)
d["k"] = 1
a, b = 1, 2              # 多目标赋值
a, b = b, a              # 交换(右侧会先全部求值到临时槽位)
a, b = input(int, int)   # 解包
lo, hi = minmax(3, 7)    # 函数多返回值解包
x += 1                   # 复合赋值
xs += [1]                # 列表就地 extend(见下)

if x < 5:
    ...
elif x < 10:
    ...
else:
    ...

while x < 10:
    ...
    break
    continue

for i in range(10):      # range(stop)
for i in range(1, 10):   # range(start, stop)
for i in range(10, 0, -3):  # range(start, stop, step)

for x in [1, 2, 3]:      # 遍历列表
for c in "abc":          # 遍历字符串,每项是长度为 1 的字符串
for k in {"a": 1}:       # 遍历字典,**产出键**(取值要写 d[k])

def add(a: int, b: int) -> int:
    return a + b

return a, b              # 返回元组
```

`range` 的三个参数在进入循环前只求值一次,循环途中改它们不影响次数 —— 与 Python 一致。
步长为 0 会在运行时给出明确报错,不会死循环。

遍历列表/字符串/字典时:

- 被遍历的对象在**进入循环时绑定一次**。循环体里给变量重新赋值不影响本轮遍历。
- 但长度**每轮重读**,所以往列表里 `append` 的元素也会被遍历到 —— 与 Python 一致。

### ⚠️ `+=` 与 `+` 在列表上不同

这是 Python 里一个真实存在、且一眼看不出来的区别,本项目特意做对了:

```python
xs = [1, 2]
alias = xs
xs += [3]          # 就地 extend
print(alias)       # [1, 2, 3]   ← 别名看得见

ys = [1, 2]
alias = ys
ys = ys + [3]      # 重新绑定
print(alias)       # [1, 2]      ← 别名看不见
```

字符串与数值不可变,所以 `s += "x"` 一定是重新绑定,别名看不到变化。

### 下标与切片

```python
xs[0]      xs[-1]        # 负索引从末尾数
s[1]                     # 长度为 1 的字符串(不是字符码)
d["k"]                   # 字典按键查找,键不存在报运行时错误
d.get("k")               # 键不存在返回 None
xs[1:4]    xs[:3]    xs[3:]    xs[:]    xs[::2]    xs[::-1]
```

切片语义完全按 Python:两端可省略、支持负索引、支持负步长,结果类型跟着原对象
(列表切出列表、字符串切出字符串、元组切出元组)。

### 内建函数

| 写法 | 说明 |
|---|---|
| `print(a, b)` | 空格分隔,末尾换行 |
| `input(int, int)` | 按类型逐个读一行,返回元组 |
| `input(int)` | 只读一个值,直接返回该值(不包成 1 元组) |
| `len(x)` | 字符串/列表/字典/元组的长度 |
| `range(...)` | 见上,只能直接用在 `for` 的迭代位置 |
| `gc_collect()` | 手动触发一次垃圾回收,返回 `None` |

`gc_collect()` 用下划线而不是 `gc.collect()` —— 语言里没有模块概念,
后者会被解析成"对变量 `gc` 做方法调用",而 `gc` 并不存在。它会遮蔽同名的用户函数。

`input` 的类型可以是 `int` / `float` / `bool` / `str`。`bool` 接受
`True`/`False`/`true`/`false`/`1`/`0`。

`print` 对容器用 repr 渲染,对顶层字符串用 str 渲染 —— 与 Python 一致:

```python
print("hi")        # hi          (不带引号)
print(["hi"])      # ['hi']      (容器内带引号)
print({"a": 1})    # {'a': 1}
```

### 方法

方法调用的形式是 `obj.method(args)`,由运行时按对象类型分派。
`obj.attr` 这种**取值**形式没有意义(本语言没有属性),会报错。

| 类型 | 方法 |
|---|---|
| str | `upper` `lower` `strip` `split` `join` `startswith` `endswith` `replace` `find` `count` |
| list | `append` `extend` `insert` `remove` `pop` `index` `count` `reverse` `sort` `clear` |
| dict | `get` `keys` `values` `items` `pop` `update` `clear` |

修改自身的方法(`append` / `sort` / `update` …)返回 `None`,与 Python 一致。

**方法名拼错是运行时错误,不是编译错误。** 本项目的类型注解不做检查,
`x.upper()` 里的 `x` 到编译期根本不知道是什么类型,所以只能运行时查找 ——
Python 自己也是这么做的。报错信息会明确指出类型和方法名:

```
Xmex error: 'str' 没有方法 'nope'
```

### 与 Python 的差异

除上述之外,还有两处刻意的差异:

- `d.keys()` / `.values()` / `.items()` 返回**普通列表**,不是视图对象。
  Python 的 `dict_keys([...])` 那套没有实现,也不需要 —— 直接用 `for` 遍历或用
  `len()` 都成立。
- `"abc".replace("", "x")` 返回原串。Python 会在每个字符前后插入,规则很绕,
  这里选择明确、可预期的行为。

## 缩进规则

与 Python 一致:

- 制表符按 8 的倍数对齐
- 空行和纯注释行不产生逻辑行,也不影响缩进层级
- 圆括号/方括号/花括号内部换行不结束逻辑行(隐式续行)
- `#` 开始注释
- 取消缩进必须回到某个已存在的层级,否则报"缩进不匹配"

变量是**函数作用域**(与 Python 相同),不是块作用域 ——
`if` / `for` / `while` 里赋值的变量在块外也能看见。

## 尚未支持

- 异常(`try` / `except`)、`import`、生成器、推导式
- 任意精度整数
- `in` 运算符(`x in xs`)—— 只有 `for ... in ...` 里的 `in`
- 三元表达式(`x if c else y`)
- `a[i] += 1` 这类**下标复合赋值**(`a[i] = ...` 是支持的)
- JIT / REPL

尝试使用未支持的特性时,编译器会给出明确提示,而不是生成错误的代码。
唯一的例外是方法名 —— 见上面「方法」一节的说明。

## 已知限制(设计取舍,不是 bug)

### 内存回收:保守式标记-清除

运行时是一个**保守式标记-清除**垃圾回收器(实现见 `runtime/gc.cpp`)。只有
`str` / `list` / `dict` / `tuple` 是堆对象,`int` / `float` / `bool` / `None`
是内联标量、根本不分配。

它**能回收循环引用** —— 这正是当初没有选引用计数的原因之一:

```python
x = []
x.append(x)      # 自引用;引用计数会永远泄漏,标记-清除能收掉
```

分配量越过阈值时自动回收(阈值按上次存活量自适应,下限 1MB),也可以手动调
`gc_collect()`。三个环境变量用于观察与排查:

| 变量 | 作用 |
|---|---|
| `XMEX_GC_STATS=1` | 每次回收与进程退出时打印统计到 stderr |
| `XMEX_GC_STRESS=1` | **每次分配都回收**。最坏情况,用于把 GC 路径逼到每轮都走 |
| `XMEX_GC_OFF=1` | 关闭自动回收(显式的 `gc_collect()` 仍然有效),用于对照 |
| `XMEX_GC_THRESHOLD=<字节>` | 覆盖自动回收的阈值 |

#### ⚠️ 根必须放在栈上

回收器靠**扫描当前线程的栈和寄存器**来找活对象,不扫描全局数据区。所以:

```python
# 在 Xmex 里这没问题 —— 变量都住在栈上的槽位里
s = "hello"
```

但如果从**手写 C++** 里长期持有 `lite::Value`,它必须是个**局部变量**(或调用了
`gc_root_push` 登记的地址)。把 `lite::Value` 放进全局变量、`static` 或
`thread_local` 里,它指向的对象会被当作垃圾回收掉。

#### 保守的代价

- **不移动、不压缩。** 对象地址稳定(手写 C++ 可以安全地长期持有),代价是会有
  内存碎片。
- **偶尔误保留。** 栈上或容器里的一个整数,如果位模式恰好等于某个对象地址,
  那个对象就会被当作活着。实际发生概率很低(小整数远低于堆地址范围),而且
  后果只是"晚一点回收",不是错误。
- 容器里的字符串内容是**不扫描**的(它不可能含有指针),所以文本本身不会造成误保留。
- **回收本身对深嵌套是安全的**:标记用的是显式栈,不是递归。实测构造 3 万层的
  嵌套列表(`x = [1]` 然后循环 `x = [x]`)完全正常。**但 `print` 它会崩** ——
  `repr` 与相等比较是递归实现的,那是它们的问题,不是回收的。

### 字典是线性扫描

`lite::Dict` 用两条平行数组 + 线性查找,不用哈希表。原因是:线性扫描天然保住了
Python 3.7 起可观测的**插入序**(遍历顺序、repr 输出都稳定),而哈希表要为
每种键类型写一份 hash 并维护一条额外的顺序链。

代价是查找、插入、删除都是 O(n)。字典一大就会明显变慢。

键按**值**比较,所以 `1` 与 `1.0` 是同一个键(与 Python 一致)。

### 没有异常

任何运行时错误(除零、类型错误、下标越界、字典缺键)都会打印消息到 stderr 然后
`exit(1)`。没有 `try` / `except`,也不会有栈回溯。

### 类型名目前只是注解

`def f(a: int)` 里的 `int` 会被解析、存进 AST,但**不做检查**。
唯一有实际作用的地方是 `input(int, int)` —— 那里决定用哪个读取函数。
